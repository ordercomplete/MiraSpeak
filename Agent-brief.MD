## 0. Як працювати (правила для агента)

1. **Спочатку план, потім код.** Перед кожним milestone напиши короткий план у `docs/plans/Mx.md` і лише тоді реалізуй.
2. **Нічого не вигадуй про API моделей і бібліотек.** Перш ніж викликати `supertonic`, `faster-whisper`, `ollama` тощо — прочитай встановлену версію (`pip show`, `help()`, README у `site-packages`) і зафіксуй версії в lock-файлах.
3. **Offline-first.** Після завантаження моделей застосунок не робить жодних мережевих запитів. Додай тест, який блокує мережу (наприклад, socket-guard у pytest) і проганяє основні сценарії.

5. **Оцінювання — детерміноване, де це можливо.** LLM пояснює, веде діалог і оцінює вільні відповіді за рубрикою; закриті завдання (MCQ, cloze, dictation) перевіряються кодом, не LLM.
6. **Рішення фіксуй** у `docs/DECISIONS.md` (дата, варіанти, чому обрано).
7. **Невідомі речі — у `docs/OPEN_QUESTIONS.md`**, а не «вгадуй». Питання, які треба задати власнику, — у розділі 6.

## 1. TTS: один локальний рушій для української і англійської

### 1.1 Що з'ясовано (пошук станом на жовтень 2026)

**Основний кандидат — Supertonic 3 (Supertone)**

- ~99M параметрів, ONNX, працює на CPU без GPU, вихід 44.1 кГц.
- 31 мова, у тому числі `uk` і `en` — **один і той самий voice style використовується для обох мов**, перемикати рушій не треба. Параметр `lang` передається у `synthesize(...)`.
- Є прості теги експресії: `<laugh>`, `<breath>`, `<sigh>`.
- Ліцензія ваг — **BigScience OpenRAIL-M** (use-based restrictions: не видавати за чужий голос без згоди, не видавати синтез за живу мову без позначки, не порушувати закон). Приклади коду — MIT. Для особистого навчального застосунку це не проблема, але **у UI має бути позначка «голос згенеровано ШІ»**.
- Готові голоси фіксовані (preset voice styles, напр. `M1`). **Клонування/створення власних голосів недоступне**: єдиний інструмент для цього (Supertonic Voice Builder) закрито.

**Критичний ризик:** компанію Supertone ліквідовують; хостингові сервіси закрито 31.08.2026, офіційний GitHub-репозиторій оголошено до архівування. Ваги можуть зникнути з офіційної організації на Hugging Face.
**Дія (обов'язкова, перша в M1):** завантаж ваги та `voice_styles/` **зараз**, збережи в `models/tts/supertonic-3/`, зафіксуй SHA-256 у `models/MANIFEST.json`, зроби резервну копію поза репозиторієм. Є дзеркало «verbatim mirror» на HF (`jiangzhuo9357/supertonic-3`, підтримується проєктом Sokuji) — використовуй його як джерело й звір контрольні суми з оригіналом, якщо оригінал ще доступний. Пакет `supertonic` з PyPI теж може зникнути — **вендоризуй wheel** у `vendor/`.

**Чого я не зміг перевірити:** якість *української* вимови Supertonic 3 (наголоси, `ґ`, апостроф, м'якість) і *англійської* з точки зору «еталонності» для учня. Це не гадаємо — це вимірюємо в bake-off (1.3).

### 1.3 Завдання M1 — bake-off (ворота: без проходження далі не йдемо)

Створи `tools/tts_eval/` і прогони кандидатів (Supertonic 3 обов'язково; VoxCPM2 і Fish S2 Pro — якщо дозволяє залізо, для порівняння якості).

**Тестовий корпус** (`tools/tts_eval/corpus.yaml`):
- 40 українських речень: омографи з різним наголосом (за́мок/замо́к, а́тлас/атла́с), `ґ`, апостроф (`'`, `’`, `ʼ` — нормалізуй), числа, дати, абревіатури, англійські слова всередині українського тексту;
- 60 англійських речень A1–B1+: мінімальні пари (ship/sheep, bad/bed, think/sink, west/vest), `th`, `h`, редукція (schwa), word stress (record n./v.), інтонація питань, числа/час;
- 20 змішаних речень: українське пояснення + англійська фраза в лапках.

**Метрики:**
1. *Round-trip WER/CER:* синтез → ASR (faster-whisper large-v3 або Parakeet-TDT-0.6B-v3; перевір підтримку `uk`) → порівняння з вихідним текстом.
2. *Швидкість:* RTF, first-audio latency, RAM — на цільовому залізі користувача.
3. *Сліпе слухання (робить власник):* генеруй пронумеровані WAV без назви моделі; форма для оцінок 1–5: природність, коректність наголосу (укр.), «чи це еталонна англійська для учня».
4. *Стабільність:* відсоток пропусків/повторів слів на 100 речень.

**Пропоновані пороги (мої припущення — власник може змінити):**
uk round-trip WER ≤ 8 %, en ≤ 5 %, RTF ≤ 0.3 на CPU користувача, середня оцінка ≥ 3.8/5, помилок наголосу ≤ 5 % на укр. корпусі.

**Вихід:** `tools/tts_eval/report.md` + аудіозразки у `tools/tts_eval/out/` + запис у `DECISIONS.md`.

**Рішення за результатом:**
- Пороги пройдено → **План A** (Supertonic 3 як єдиний рушій).
- Англійська добра, українська слабка лише через наголоси → спершу пом'якшення (1.4), потім перевірка заново.
- Українська не проходить → **План B** (дотренування, 1.5).
- План B недоступний (немає GPU / даних) → **План C**: два рушії за єдиним `TTSProvider` з підбором тембрів, максимально наближених між собою. Це запасний варіант, не ціль.

### 1.4 Архітектура TTS-сервісу

```python
# packages/core/tts/provider.py
from typing import Protocol, Literal
from dataclasses import dataclass

Lang = Literal["uk", "en"]

@dataclass(frozen=True)
class Span:
    text: str
    lang: Lang

@dataclass
class Audio:
    pcm: bytes          # 16-bit mono
    sample_rate: int
    duration_s: float

class TTSProvider(Protocol):
    name: str
    version: str
    def voices(self) -> list[str]: ...
    def synthesize(self, text: str, lang: Lang, voice: str, speed: float = 1.0) -> Audio: ...
```

Обов'язково:
- **Сегментація змішаного тексту:** розбий рядок на `Span` за скриптом (кирилиця/латиниця) і явною розміткою `<en>…</en>`; кожен span синтезується з власним `lang`; з'єднання з коротким кросфейдом (≈30 мс) і природною паузою.
- **Нормалізація тексту** окремо для `uk` та `en` (числа, дати, скорочення; для uk — `num2words(lang="uk")`, нормалізація апострофа; прибрати комбінівні наголоси, якщо рушій їх не розуміє).
- **Наголоси (uk):** словник `ukrainian-word-stress` (lang-uk, MIT) використовуй *для перевірки й анотації корпусу та UI-підказок*, не покладайся, що рушій читає знак наголосу. Для спірних слів у навчальному тексті переформулюй речення.
- **Кеш на диску:** ключ = `sha256(text|lang|voice|speed|model_version)`. Аудіо курсу **попередньо генерується під час збірки контенту** (`make content-audio`); у реальному часі синтезується лише діалог із LLM.
- **Режими:** `normal`, `slow` (0.7–0.8 для дрилів), побуквений/пофразовий. Потокова віддача по реченню.
- **Вирівнювання слів для «караоке»:** якщо рушій не віддає таймінги — отримуй їх forced-alignment'ом (ASR із word timestamps) під час збірки контенту.
- Позначка «AI-generated voice» у UI (вимога ліцензії).

### 1.5 Якщо потрібно навчити/дотренувати (План B)

**Реалістична стратегія: дотренування готової багатомовної моделі, а не тренування з нуля.**

**B1. LoRA/SFT VoxCPM2 на українській**
1. Дані: відкриті українські корпуси (`egorsmkv/ukrainian-tts-datasets`; Common Voice `uk` — лише відфільтровані чисті записи, CC0; **перевір ліцензію кожного датасету** і запиши в `data/LICENSES.md`). Бажано 1–2 дикторів, студійна якість.
2. Підготовка: resample → VAD-нарізка 3–15 с → транскрипція/звірка ASR (відкинути сегменти з WER > 10 %) → нормалізація гучності → манифест (`audio_path|text|speaker|lang`) для формату, який вимагає репозиторій VoxCPM (**прочитай його fine-tuning docs, не вгадуй формат**).
3. Змішай ~20–30 % англійських даних тієї ж якості (LibriTTS-R або власний запис), щоб не втратити англійську й зберегти *однаковий тембр*.
4. Smoke-тест на малому наборі (десятки хвилин) — лише щоб перевірити пайплайн. Офіційні «5–10 хвилин» стосуються адаптації голосу; **для навчання мови, якої модель не знала, очікуй потребу в годинах даних (десять і більше) — це моя оцінка, її треба підтвердити експериментом.**
5. Оціни тим самим bake-off. Запиши вимоги до VRAM, час навчання, гіперпараметри в `docs/tts_training.md`.

**B2. Крайній випадок:** власна багатомовна VITS/StyleTTS2 з language embedding на об'єднаному uk+en корпусі. Дорого й ризиковано — лише якщо B1 не вдався.

Єдиний інтерфейс `TTSProvider` не змінюється при заміні моделі — тест-сьют TTS має проходити для будь-якої реалізації.

## 2. Навчальний план і система перевірки знань

### 2.1 Цільова рамка

- Шкала: CEFR. **Стеля курсу — B1+ (верх Intermediate).** B2 (Upper-Intermediate) поза обсягом, але модель даних має дозволяти додати рівень без міграцій.
- Рівні: **Placement → A1 → A2 → B1 → B1+**.
- Орієнтир за навчальними годинами (Cambridge guided learning hours, кумулятивно з нуля): A1 ≈ 90–100 год, A2 ≈ 180–200, B1 ≈ 350–400. B1+ — ще ≈ 80–100 год понад B1 (моя оцінка).
- При 5 год/тиждень: A1 ≈ 20 тижнів, A2 ≈ 20, B1 ≈ 40, B1+ ≈ 18. При 10 год/тиждень — удвічі швидше. Застосунок показує **персональний прогноз**, а не фіксовані дати.
- Активний словник (орієнтир, кумулятивно): A1 ≈ 700, A2 ≈ 1 500, B1 ≈ 2 500, B1+ ≈ 3 500 лем.
- Джерело лексики: NGSL (CC BY-SA) + CEFR-J Wordlist. **Агент перевіряє ліцензії перед включенням.** Не копіюй закриті списки (Oxford 3000/5000, EVP) у репозиторій.

### 2.2 Структура одиниці (Unit, 60–90 хв матеріалу, 3–4 сесії по 20–25 хв)

1. **Warm-up** — SRS-повторення карток з попередніх одиниць (5 хв).
2. **Input** — діалог або короткий текст з аудіо (TTS), з перемикачем «текст/без тексту».
3. **Notice** — коротке граматичне пояснення **українською** з порівнянням «чим відрізняється від української» (L1-contrast).
4. **Controlled practice** — закриті вправи з автоперевіркою.
5. **Production** — говоріння/письмо за рубрикою (оцінка LLM + детермінована перевірка).
6. **Pronunciation micro-drill** — 1 звук/ритм-патерн за одиницю.
7. **Unit test** — 15–20 завдань; ворота: **≥ 80 %** і ≥ 70 % retention по SRS-картках попередніх одиниць.

Принципи: коротке пояснення → багато практики; новий матеріал одразу потрапляє в SRS; «Український суфлер» — частка української в поясненнях знижується з рівнем (A1 ≈ 80 % → B1+ ≈ 20 %; налаштовується).

### 2.3 Силабус

**Звукова доріжка для україномовних (наскрізна):**
`th /θ ð/`; `w` vs `v`; `h /h/` (не укр. `г`/`х`); довгі/короткі голосні (`ship/sheep`, `full/fool`); `/æ/` vs `/e/`; **не пом'якшувати приголосні перед `i`/`e`** (укр. палаталізація); придихання `p t k`; редукція й шва `/ə/`; наголос у слові та ритм фрази; `-ed`/`-s` закінчення; `ŋ`; `r`, темне `l`; зв'язне мовлення (linking, weak forms) — з B1.

**Типові граматичні інтерференції з української (теги помилок):** відсутність артиклів; порядок слів; зайве/пропущене `be`; `Present Perfect` vs `Past Simple`; прийменники; подвійне заперечення; `-ing` форми; род. відмінок ↔ `of`/`'s`; `since/for`; `make/do`; `say/tell`. **Хибні друзі:** actual/актуальний, accurate/акуратний, magazine/магазин, fabric/фабрика, intelligent/інтелігентний, data/дата, sympathetic/симпатичний, decade/декада, ...

#### A1 (12 одиниць)
| № | Тема | Граматика / функції |
|---|---|---|
| 1 | Знайомство | алфавіт і spelling, to be, особові займенники, числа 0–100 |
| 2 | Люди й родина | присвійні, `'s`, this/that/these/those, a/an |
| 3 | Щоденне життя | Present Simple (+/−/?), час, дні, adverbs of frequency |
| 4 | Дім і місця | there is/are, прийменники місця, the/a/zero (вступ до артиклів) |
| 5 | Їжа й покупки | countable/uncountable, some/any, how much/many |
| 6 | Здібності й уподобання | can/can't, like/love/hate + -ing |
| 7 | Зараз | Present Continuous vs Simple |
| 8 | Минуле 1 | was/were, Past Simple (правильні) |
| 9 | Минуле 2 | неправильні дієслова (топ-40), питання з did |
| 10 | Плани | going to, would like / want to |
| 11 | Подорожі й напрямки | imperative, прийменники руху, транспорт |
| 12 | Повторення + **Checkpoint A1** | — |

Can-do: представитися, питати/відповідати про особисте, замовити їжу, спитати дорогу, написати коротке повідомлення.

#### A2 (16 одиниць)
Порівняння (comparatives/superlatives), Past Continuous, Present Perfect (досвід, just/already/yet, for/since), will vs going to, must/have to/should, перша умовна, quantifiers, adverbs, об'єктні займенники, базові phrasal verbs, gerund/infinitive (базово), used to, relative clauses (who/which/that), прості індиректні питання.
Теми: здоров'я, подорожі, робота, хобі, шопінг, погода, технології, розповідь про минуле, запрошення/пропозиції/вибачення.
Письмо: неформальні листи/повідомлення 60–100 слів. Checkpoint кожні 4 одиниці, **Level exit test A2**.

#### B1 (20 одиниць)
Контраст часів (Present Perfect Simple/Continuous, Past Perfect), narrative tenses, Passive (Present/Past/Perfect), друга умовна і вступ до третьої, reported speech, modals of deduction (might/must/can't be), defining/non-defining relative clauses, gerund vs infinitive повністю, used to/would, wish/if only (вступ), question tags, as…as / the more…the more, артиклі детально, phrasal verbs (separable), linking words (although/despite/however), майбутні форми (will/going to/Present Continuous/Future Continuous).
Теми: робота й освіта, медіа, довкілля, здоров'я, стосунки, культура, думки й аргументи.
Навички: розповідь, порівняння, висловлення думки, листи/ел. пошта, ессе 120–150 слів, аудіо у сповільненому/нормальному темпі з однією-двома акцентами.
**Level exit test B1.**

#### B1+ (12 одиниць, «міст до B2»)
Змішані умовні, Passive розширено (включно з reporting passive), reporting verbs, Future Perfect, wish/regret, causative `have/get`, participle clauses (вступ), колокації, ідіоми-мінімум, hedging, формальний vs неформальний регістр, структура аргументативного ессе, переказ/summary, природнє мовлення різних акцентів, дискурсні маркери.
**Final exit test B1+.**

### 2.4 Система оцінювання

#### A. Placement (адаптивний, 15–25 хв)
- Банк ≥ 300 айтемів, розмічених за рівнем і can-do (лексика, граматика, читання, аудіювання).
- Алгоритм: старт з A2; адаптивна сходинка (вгору/вниз) або спрощена IRT/Rasch; зупинка за стабілізацією оцінки або після 30 айтемів.
- Додатково: **говоріння** (30 с відповіді на запитання — STT + рубрика) і **письмо** (3–4 речення — рубрика).
- Вихід: початковий рівень **по кожній навичці окремо** + рекомендований стартовий юніт. Користувач може погодитись/змінити.

#### B. Типи завдань і хто перевіряє

| Тип | Перевірка |
|---|---|
| MCQ, matching, drag-order, cloze (вибір/введення) | Код (детермінована) |
| Dictation (TTS → друк) | Код: нормалізована відстань Левенштейна + diff-підсвітка |
| Переклад UK→EN | Код (набір прийнятних відповідей) + LLM-арбітр лише для відсутніх варіантів |
| Error correction | Код (очікувана правка) + LanguageTool |
| Listening comprehension | Код (аудіо з TTS, закриті запитання) |
| Говоріння | STT + вирівнювання/GOP-подібна оцінка вимови (**показуємо як фідбек, не як оцінку в gate**) + LLM-рубрика зв'язності/лексики |
| Письмо | LanguageTool (детерміновано) + LLM-рубрика (task achievement, grammar, vocabulary, coherence) |

#### C. Модель майстерності
- Для кожного **can-do** і **граматичного пункту** — оцінка 0–1 (BKT або Elo/IRT на айтем).
- **SRS: FSRS** (пакет `fsrs`) для лексики, граматичних патернів і *власних помилок*.
- Ворота юніта: ≥ 80 % unit test + ≥ 70 % retention.
- **Checkpoint** кожні 4 одиниці (змішаний, включно зі старим матеріалом).
- **Level exit test** (60–90 хв: Use of English, Reading, Listening, Writing, Speaking): прохід — ≥ 75 % загалом і ≥ 60 % по кожній навичці.
- **Відкладені ретести** (7 / 30 / 90 днів) на раніше «засвоєний» матеріал; падіння нижче порога повертає елемент у активний SRS.

#### D. LLM-оцінювач — запобіжники
- Вихід лише за JSON-схемою (рубрика з балами й обґрунтуванням, цитати з тексту учня).
- `temperature = 0`, двопрохідна оцінка для gate-завдань; розбіжність > 1 бала → «потребує людського перегляду».
- **Калібрувальний набір:** 30 розмічених вручну зразків письма/мовлення (агент готує, власник розмічає) → `tests/llm_grading/`; регресійний тест при зміні моделі/промпту.
- Усі сирі відповіді LLM зберігаються для аудиту.

#### E. Банк контенту і його якість
Схема айтема (YAML/JSON):
```yaml
id: a1-u03-cloze-017
level: A1
skill: grammar            # vocab|grammar|listening|reading|speaking|writing
can_do: A1.GRAM.PRES_SIMPLE
type: cloze_input
prompt_en: "She ___ (work) in a bank."
answers: ["works"]
accepted: []
explanation_uk: "Для he/she/it у Present Simple додаємо -s."
l1_tags: [third_person_s]
audio_ref: null
difficulty_prior: 0.2     # оновлюється за статистикою
source: generated+reviewed
qa_status: reviewed       # draft|auto_checked|reviewed
```
**Пайплайн якості:** генерація LLM → валідатор схеми → дедуплікація → перевірка рівня лексики (частка слів вище цільового рівня ≤ 5 %) → друга модель перевіряє ключ відповіді → вибірка 20 % у чергу людського рецензування → лише потім `qa_status: reviewed`. Контент у `content/` версіонується, зміни — через PR.

**Обсяги (мінімум):** ~40 айтемів на юніт, 12–16 діалогів/текстів на рівень, 300 placement-айтемів, 3 варіанти кожного exit-тесту.

## 3. Рекомендована структура застосунку (мої пропозиції)

### 3.1 Стек (пропозиція; узгодити з власником, див. розділ 6)
- **Monorepo.** `apps/web` (React + TypeScript + Vite; пізніше за потреби обгортка Tauri), `services/api` (Python 3.12, FastAPI), `packages/core` (доменна логіка: оцінювання, SRS, TTS-інтерфейси), `content/` (курс як дані), `tools/` (bake-off, генерація й валідація контенту), `models/` (ваги, не в git; `MANIFEST.json` у git).
- **Дані:** SQLite (профіль, прогрес, відповіді, SRS-стан), файли для аудіо/кешу. Бекап/експорт одним архівом.
- **Провайдери:** LLM через OpenAI-сумісний локальний ендпоінт (Ollama/llama.cpp); STT — faster-whisper (або Parakeet v3); TTS — Supertonic 3 (ONNX Runtime); граматика — LanguageTool (локальний сервер, є en і uk); fonetic — `phonemizer` + espeak-ng.
- **Інструменти:** `uv` (Python), `pnpm` (web), `make check`, pre-commit. Крос-платформно (уточнити ОС).
- **Вибір LLM:** вимірювати, а не вгадувати. Кандидати для локального запуску — Gemma-сімейство (є українські дотренування, наприклад MamayLM на базі Gemma) та Qwen-сімейство; створити невеликий eval (20 пояснень граматики українською + 20 рольових діалогів на A2/B1) і обрати за якістю української/англійської та швидкістю на залізі користувача. **Профілі заліза** `low/mid/high` у конфігу задають моделі за замовчуванням.

### 3.2 Функціонал за етапами

**MVP**
- Онбординг, вибір голосу/швидкості, Placement.
- Курсова стежка A1 (спершу юніти 1–3 як вертикальний зріз), exercise-engine з автоперевіркою.
- SRS (FSRS), щоденна сесія «до 20 хв» (черга: due-картки → поточний юніт → слабкі місця).
- TTS з кешем, відтворення слово/фраза/діалог, повільний режим.
- Дашборд прогресу: рівень по навичках, streak, прогноз, слабкі теми.
- Model Manager: завантаження/перевірка SHA/версії, профіль заліза, діагностика «що запущено локально».

**v1**
- **AI-партнер для діалогу:** рольові сценарії за рівнем (кафе, співбесіда, лікар, подорож); системний промпт обмежує складність (CEFR-лексика, довжина реплік), перемикач підказок українською.
- **Політика виправлень:** під час розмови — *recast* (мовби переказ правильно) без зупинки; повний розбір помилок — **після** діалогу. Помилки автоматично потрапляють у «Зошит помилок» і SRS.
- **Говоріння:** запис → STT → розбір по словах; фонемний фідбек «ось де розійшлося» з приміткою про український вплив; **shadowing** (слухай → повтори → порівняй).
- **Письмо:** LanguageTool + LLM-рубрика, пояснення українською, перепис тексту з виправленнями.
- **Мінімальні пари / дрили вимови** з прив'язкою до звукової доріжки.

**v2**
- Graded reader: LLM генерує короткі історії під рівень → перевірка рівня лексики → TTS з підсвіткою слів («караоке»), клік по слову → переклад/картка в SRS.
- Імпорт власних текстів: розмітка за рівнем, добірка невідомих слів.
- Аудіювання зі змінною швидкістю, диктанти.
- Експорт в Anki, нагадування, тижневі звіти.
- Конфіг «англійська: US/UK» (потрібен відповідний голос/дані — залежить від результату bake-off).

### 3.3 Принципи UX і продукту
- **Українськомовний інтерфейс** і пояснення з L1-контрастом; слайдер «скільки української».
- Короткі сесії (10–25 хв), чіткий «наступний крок» на головному екрані.
- Помилка = дані: кожна помилка тегується (категорія, L1-джерело) і живить повторення.
- **Прозорість оцінок:** користувач бачить, чому поставлено бал (рубрика, цитати).
- Доступність: клавіатурна навігація, масштаб шрифту, темна тема, субтитри до аудіо.
- Приватність: жодної телеметрії; логи лише локально; один архів для експорту/видалення.
- Тест «мережі немає»: основні сценарії проходять із вимкненим інтернетом.

### 3.4 Чого агент **не** робить
- Не викликає хмарні API (LLM/TTS/STT) — навіть «тимчасово».
- Не віддає LLM перевірку закритих завдань і ключів.
- Не додає в репозиторій контент із невідомою ліцензією.
- Не змінює пороги, схему оцінювання чи вибір рушія TTS без запису в `DECISIONS.md` і схвалення власника.

## 6. Відкриті питання до власника (агент має спитати/зафіксувати припущення)

1. **Залізо:** ОС, CPU, RAM, GPU (модель, VRAM)? Від цього залежать LLM, STT і чи реальний План B.

3. **Варіант англійської:** американська чи британська? (визначає еталонний голос і вимовні дрилі).
4. **Стеля курсу:** підтверджуєте B1+ як максимум, чи потрібен B2?
5. **Ваш поточний рівень** і скільки годин на тиждень можете вчитися (для прогнозу й пейсингу).
6. **Голос:** чоловічий/жіночий; вибір за результатами сліпого прослуховування.
7. **Хто рецензує контент і калібрувальні зразки:** тільки ви чи залучаєте викладача?
8. **Ліцензії:** лише особисте використання чи потенційно розповсюдження? (впливає на OpenRAIL-M, ліцензії датасетів і моделей).
