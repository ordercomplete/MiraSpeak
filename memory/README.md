# MiraSpeak — памʼять розробки (журнал змін)

Файли за датами. Кожен файл `YYYY-MM-DD.md` створюється у день першого запису,
всередині — записи з точним часом змін. Наступна доба → новий файл.

Порядок записів: від старих до нових, формат `- [HH:MM] текст`.

## Правила ведення журналу

1. **Записувати зміни в `memory/YYYY-MM-DD.md` до коміту** — щоб журнал не відставав
   від репозиторію (2026-10-20: зміни сесії 19–20.10 не були записані, довелося
   відновлювати журнал заднім числом).
2. **Після кожної правки `static/index.html` проганяти дві перевірки**:
   - синтаксична перевірка витягнутого `<script>` (`node --check`) — 2026-10-20 через зайву `}` увесь
     фронтенд перестав виконуватись (кнопки, діалог, історія чатів були мертві, поки API працював);
   - перевірка структури хвосту HTML — 2026-10-20 файл виявився обрізаним без `</script>`, `</body>`, `</html>`,
     тому браузер не закрив блок `<script>` і **жоден** JS-код не виконався (теж саме — мертвий UI при живому API);
   - **`node --check` не виявляє відсутність `</script>`** — потрібна окрема перевірка структури HTML
     (кількість `<script>`/`</script>`, наявність `</body></html>` у кінці файлу).
3. Формат файлу: `# YYYY-MM-DD`, далі записи від старих до нових, у кожному —
   час, коміт (якщо є) і суть зміни.
4. **Ніколи не замінювати ділянку «від останнього слухача до EOF» у `static/index.html`** —
   тільки вузькі анкори. Патч-скрипти саме так у 2026-10-20 видалили хвост файлу разом із closing-тегами.
